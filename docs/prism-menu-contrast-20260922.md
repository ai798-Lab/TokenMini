# Prism 菜单文字对比度修复 · 2026-09-22

## 问题与范围

用户截图中的菜单栏面板，右上角“外观”按钮出现深色背景、近黑文字，图标却保持浅色。之前的验收遗漏了正式菜单栏面板，主窗口验收不能覆盖这个入口。

已安装 build 6 的二进制 SHA256 与 5187 工作区 dist 逐字节相同，因而在该工作区实施修复；当前任务 a586 工作区仍是较早的 MacPulse 基线，不覆盖它的源码。保留 5187 原有未提交修改。

## 实施

- “外观”的文字与图标均直接声明暖白前景色，避免仅在 Menu 外层使用 tint/foregroundStyle 时，原生文字和符号解析不一致。
- 共享 ThemedMenuLabel 的文字、箭头也直接声明前景色：普通菜单暖白字，选中菜单深色字；覆盖监控台及 Skills 筛选。
- ThemedMenuChrome 增加 plain button 样式声明；原调用点仍有 borderlessButton 声明，不能将这一项单独视为原生样式问题已解决的证据。
- 未改数据、采集、清理、账号或公开发布路径。

## 未完成的真实验收

UI 自动化每次连接/激活应用会触发 applicationShouldHandleReopen，并通过 MacPulse.openMaintenance 打开清理窗口。面板的可访问性树曾被读到，但随后的截图切换成了清理页，菜单操作还出现 element ID is no longer valid。SystemUIServer/ControlCenter 入口超时。不能把清理窗口截图算作原问题的视觉验收。

因此，本记录只确认代码、构建、安装及冷启动；菜单栏“外观”按钮修复后的视觉、菜单展开/收起、主题往返与全部同类控件状态仍待真实界面验收。不得宣称“彻底解决”或“全部 UI 验收通过”。

## 后续皮肤/控件改动的交付门槛

每次更改共享菜单文字或背景，必须在正式安装入口完成并留下截图证据：

1. 菜单栏面板与完整监控台分别检查；任何一个不能由另一个代替。
2. “外观”及工具/项目/模型/Token 构成/Skills 菜单，检查普通、选中、悬停、禁用状态。
3. 暖白/浅色字与深底配对；深色字仅搭配浅色或亮色选中底。文字、符号均检查，不能仅凭图标可见判定。
4. 点开、关闭菜单后颜色不退回；Prism 与 Classic/HUD/LED 往返后检查，最终恢复原主题。
5. 至少检查系统浅色/深色外观以及窄/常规监控台宽度，文字不截断、按钮不重叠。
6. 自动化阻塞时记录未验收，不用编译/测试/间接截图填“通过”。

这些是项目验收要求，不是已经执行完成的结果，也不构成“永不复发”的保证。
